Astra Developer Platform и разработка на 1С

Срез публичных материалов на 27 ноября 2026 года.

Astra Developer Platform (ADP) объединяет GitFlic для исходников и CI/CD, "Боцман" для управления инфраструктурой и инструменты наблюдения за приложениями. В анонсе 19 мая 2026 года Astra также описала слой ИИ для работы по циклу разработки. Для команды 1С практический вопрос в том, какой компонент сможет собрать ее конфигурацию, запустить тесты на нужной версии платформы и показать результат ревьюеру. Проект и исходники ADP выдает сервис с репозиторием, CI/CD и записью в каталоге; шаблоны задают стандартный путь разработки. Выбрать формат исходников (EDT или выгрузка конфигурации), закрепить версии 1С/EDT и ветвление. BSL и EDT ADP не называет.
Разработка ADP показывает OpenIDE и "LLM/агенты"; OpenIDE Pro подключает агентов. Добавить средства BSL и метаданных. BSL Language Server выпущен сообществом 1c-syntax, не ADP/GitFlic.
Сборка и тесты GitFlic CI/CD запускает jobs и хранит артефакты. Документированы MR pipeline, Merge Result Pipeline и отчеты JUnit, SAST, DAST. Связать runner с EDT CLI/пакетным конфигуратором, тестовой базой и отчетами. По документации 1С, EDT CLI подготавливает проект для сборки конфигуратором; сценарии и команду тестов задайте отдельно.
Поставка и эксплуатация ADP заявляет среды разработки, тестирования и предпродакшна, стандарт деплоя, откат и наблюдаемость. "Боцман" управляет Kubernetes-кластерами и приложениями. Настроить доставку артефакта 1С, обновление базы, миграции и откат. Kubernetes не подтверждает готовую контейнеризацию платформы или базы 1С.

Документы 1С: сборка CI через EDT CLI, FAQ EDT, сценарное тестирование. Интеграцию с ADP надо проверить и настроить.

Gates и тесты

GitFlic позволяет назначить согласующих, запретить автору аппрувить изменения, сбрасывать аппрувы после коммита и требовать успеха pipeline. Merge Result Pipeline доступен в Enterprise. Это общие gates; правила для 1С не опубликованы.

Job может вызвать LLM через скрипт/API и сохранить unified diff как артефакт. Разработчик просматривает и применяет патч в веб-интерфейсе; затем проверки запускаются заново. Модель и поставщик не заданы. Источники: LLM-патчи, 06.05.2026, pipeline, правила слияния, справочник CI/CD YAML.

Для gate 1С нужны BSL-проверки, сборка, тесты на отдельной базе и проверка обновления. Такая цепочка в документации ADP/GitFlic не описана.

BSL, EDT, ACP и MCP

В проверенных открытых материалах Astra и GitFlic не нашлось описания выпущенной интеграции ADP с BSL, 1С:EDT или MCP для 1С.

В списке языков OpenIDE (Java, Kotlin, Go, JavaScript, TypeScript, Python, PHP) BSL не указан.

В пресс-релизе OpenIDE Pro 2026.2 (24.09.2026) ACP назван протоколом подключения агентов: Astra AI Code, Claude Code, Codex, OpenCode и Cursor. Модели вызываются через выбранного агента, конкретные не указаны. Это функция OpenIDE Pro, не поддержка MCP в ADP.

В проекте сообщества 1c-syntax расширение VS Code запускает BSL Language Server с MCP endpoint. Поддержка этой интеграции в ADP требует отдельного подтверждения поставщика. Проверьте версию и передачу контекста. Источники: релиз OpenIDE Pro, BSL Language Server, настройки расширения VS Code и MCP.

Четыре свидетельства при выборе

Перед выбором поставки запросите четыре свидетельства:

  1. Данные. На обезличенном фрагменте проверьте, какие исходники видит агент, что уходит в запрос и где хранятся контекст/журналы. Зафиксируйте внешние адреса и исключенные каталоги.
  2. Конфигурация. На закрепленных версиях 1С/EDT/runner соберите артефакт в чистом контуре, запустите BSL-проверки и сохраните версии, команды и результаты CI.
  3. Контур и LLM. Получите схему трафика выбранной поставки, название агента, протокол (ACP или MCP), модель и endpoint. Проверьте отключение внешних вызовов. ACP в OpenIDE Pro не доказывает MCP в ADP.
  4. Поддержка. Запросите матрицу версий ОС, GitFlic, "Боцмана", EDT, платформы 1С, runner и агента, сценарии сборки/тестирования/обновления, зоны ответственности и сроки поддержки. В рассмотренной документации найти такую матрицу для 1С не удалось.

При выборе ADP оцените отдельно общие функции платформы и затраты на подключение вашей конфигурации. Основанием включить поддержку 1С в требования к поставке послужат версия продукта, матрица совместимости и отчет о сборке и тестах.
