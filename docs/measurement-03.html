Пример чтения

В строке SYNTHETIC_DEMO запланировано пять обязательных проверок. Четыре пройдены, одна пропущена. Несмотря на успешные тесты, выпуск заблокирован, quality_guardrail_pass=no. Планируемый release_id не входит в показатели продуктивных развертываний. Указанная сумма отражает только записанные расходы по задаче. Пример вымышленный и не описывает фактическую работу команды.

Для учета используйте журнал задач (CSV). Строка с типом SYNTHETIC_DEMO приведена только для демонстрации формата.

Короткий словарь CSV

  • date, period, team_group, system_id, process_version задают дату задачи, период сводки, группу команды, ИС и применявшийся порядок работы.
  • task_id, task_class, complexity описывают единицу учета. platform_version и configuration_version фиксируют окружение.
  • ai_tool, ai_tool_version, model_id, ai_used, ai_request_count, ai_request_minutes фиксируют фактическое применение ИИ. Часы проверки и переделки ответа лежат в ai_review_rework_hours.
  • task_to_ready_hours и ready_to_release_hours измеряют календарное время на уровне задачи. Остальные поля с _hours измеряют человеко-часы. ai_request_minutes измеряются минутами. Поля с _rub измеряются рублями.
  • release_id, release_status, deployed_at, release_failed_immediate, release_rework_unplanned, recovery_minutes относятся к продуктивному развертыванию. Агрегируйте их один раз на пару system_id и release_id. Статус deployed означает, что продуктивная выкладка состоялась, даже если ее потом откатили. blocked означает, что продуктивного развертывания не было.
  • required_checks_* и tests_* содержат число запланированных, пройденных, проваленных и пропущенных проверок. task_has_defect_14d и defect_observation_matured отслеживают дефект задачи после выпуска.
  • quality_guardrail_pass равно yes только если выпуск разрешен по всем обязательным условиям. notes хранит короткую оговорку о данных.
