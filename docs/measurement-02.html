Как читать CSV

В пилоте одна строка описывает одну задачу. task_id уникален. Запишите дату, группу, версии платформы и конфигурации, инструмент/агента и модель. release_id одинаков у всех задач одного релиза.

В статистике выпусков сначала оставьте одну запись на каждый release_id со статусом deployed. Поля deployed_at, release_failed_immediate, release_rework_unplanned и recovery_minutes относятся к релизу. Заполняйте их один раз либо повторяйте одинаковое значение по строкам. Агрегируйте их по уникальному release_id, не по строкам задач.

Задачу с дефектом считайте один раз по уникальному task_id, если дефект подтвердили в 14-дневном окне. Для задачи с несколькими поставками укажите выпуск, в котором пользователь получил принятый результат. Сохраните одну строку задачи и один раз посчитайте ее стоимость. Для DORA возьмите полный список поставок и повторных развертываний из журнала CI или журнала выпусков, включая поставки без новых карточек.

task_to_ready_hours считает календарное время от принятия задачи до готовности к выпуску. change_lead_time_hours считает время от первого коммита до продуктивного выпуска. ready_to_release_hours показывает ожидание между этими точками. Для незапущенных или не выпущенных задач релизные длительности оставляйте пустыми.

План проверок задавайте заранее. Для каждой задачи должно выполняться равенство required_checks_planned = required_checks_passed + required_checks_failed + required_checks_skipped. Доля успешных проверок равна passed / planned. Пропущенная проверка остается в знаменателе. Аналогично ведите план, успехи, сбои и пропуски тестов.

ai_request_count и ai_request_minutes показывают число и суммарное время запросов к ИИ. ai_suggestions_reviewed и ai_suggestions_accepted_without_change считают рассмотренные и принятые без смысловой правки предложения. ai_review_rework_hours содержит только труд на проверку и переделку вывода ИИ. Эти часы уже входят в total_person_hours.

Для полной стоимости задачи умножьте total_person_hours на согласованную ставку и добавьте прямые расходы на ИИ. Для отдельной оценки затрат, вызванных применением ИИ, сложите прямые расходы с ai_review_rework_hours × ai_labor_rate_rub. Не прибавляйте эту оценку к полной стоимости труда второй раз.

Демо показывает задачу с одной пропущенной обязательной проверкой. Ее нельзя выпускать. release_id отражает запланированный релиз, который не входит в DORA-метрики. quality_guardrail_pass=no фиксирует решение заблокировать выпуск, несмотря на успешные тесты.

Поля ai_tool, ai_tool_version и model_id позволяют сравнить результат при конкретном инструменте и версии. Не подменяйте ими группу, назначенную задаче до начала работы.
