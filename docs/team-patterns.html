Как организовать разработку 1С с ИИ

ИИ помогает разобрать заявку, найти место правки, подготовить тест и сверить код с требованием. Команда продолжает работать в Конфигураторе с хранилищем версий 1С или в среде разработки 1С:EDT с Git, системой ведения истории исходников. Решение о выпуске принимает человек после проверки на тестовой базе.

От заявки до версии, которую можно выпустить

Ведите одну карточку на изменение. В ней нужны согласованный пример, версия и результат проверки. Каждый участник передает следующему конкретный результат.

  • Заказчик дает пример и ожидаемый результат.
  • Разработчик указывает версию изменения.
  • Проверяющий воспроизводит пример под рабочей ролью.
  • Ответственный за выпуск устанавливает принятую версию.
  • Поддержка добавляет случай сбоя в набор тестов.

Перед разработкой аналитик записывает в карточку роль пользователя, исходные данные, действие и ожидаемый результат. Указывает конфигурацию, границы изменения и кто примет работу. Если два участника ожидают разного результата, заказчик разбирает конкретный пример.

При разработке команда выбирает путь по тому, где уже хранит версии. Разработчик связывает изменение с карточкой. Проверяющий должен суметь получить ровно эту версию.

Конфигуратор и хранилище 1С. Разработчик обновляет рабочую конфигурацию, захватывает нужные объекты, меняет и проверяет их у себя, затем помещает их в хранилище с номером задачи. Коллега получает номера версий до и после, сравнение объектов и тестовую базу с проверяемой версией.

1С:EDT и Git. Разработчик создает ветку задачи, меняет проект, фиксирует изменения коммитом и открывает запрос на слияние. Коллега получает ссылку на запрос, точный коммит, разницу в исходниках и результаты проверок для этого коммита.

В Конфигураторе захват и помещение объектов входят в механизм групповой разработки. EDT поддерживает Git, сравнение и объединение изменений. Групповая разработка в 1С, возможности EDT.

Перед выпуском коллега проверяет изменения и отчет об испытаниях. Ответственный вносит в карточку версию, порядок восстановления и результат установки. Если после проверки поменяли код, коллега повторяет затронутые проверки на новой версии.

После выпуска поддержка связывает обращение с версией и первым примером, на котором проявился сбой. Команда добавляет этот пример в набор проверок. В небольшой команде один человек может вести несколько этапов. Для прав, движений и переноса данных назначьте второго проверяющего до начала работы.

Четыре задания для ИИ, которые можно повторять

1. Разобрать устную заявку. Если пользователь просит "правильно считать скидку", предложите помощнику задание "Выпиши условия из заявки. Дай примеры ниже порога, на пороге и выше. Какие вопросы еще открыты?" Аналитик показывает примеры заказчику. Любое придуманное помощником условие возвращается на уточнение.

2. Найти место изменения. Разработчик просит помощника "Найди объект, процедуру и место вызова в перечисленных модулях. Сравни правку в расширении с правкой основной конфигурации. Назови недостающие сведения". Разработчик сверяет план с метаданными проекта, и разрешает правку в рабочей копии. Если место вызова не подтверждается, разработчик уточняет план с владельцем модуля до правки. Перед ревью проверяет, что изменились только согласованные объекты.

3. Написать тест по бизнес-правилу. Передайте помощнику согласованные примеры и задание "Подготовь входные данные и ожидаемые результаты. Отдельно опиши повторное проведение". Тестировщик сверяет ожидания с заказчиком. Если тест проходит и на прежней версии с известной ошибкой, тестировщик возвращает сценарий на доработку. Для исправления ошибки сохраняет результаты одного сценария на двух версиях. На исходной виден дефект, на исправленной получен ожидаемый результат.

4. Проверить чужое изменение. Проверяющий дает помощнику задание "Сопоставь изменение с примерами приемки. Для каждого замечания укажи строку, условия и способ проверки". Коллега воспроизводит замечания и записывает решение. Если проверка под рабочей ролью провалилась, задачу возвращают разработчику.

В 1С:Напарнике для EDT есть режимы планирования и исполнения, инструкции проекта и навыки. Сохраните в проекте шаблон задания, разрешенные действия и пример принятой работы. Бета-версию API для интеграции с конвейером фирма 1С анонсировала с 1 декабря 2026 года. Руководство, анонс от 25 ноября.

Она охватывает воспроизведение, переработку с созданием производных произведений и баз данных, распространение, доведение до всеобщего сведения и публичный показ. Есть ли у вашей команды полномочия предоставить такие права на код заказчика? Согласуйте допустимые исходники с владельцем данных. Для проверок выделите тестовую базу. Доступ к выпуску оставьте ответственному сотруднику.

Сколько проверок нужно конкретной задаче

  • Подпись или расположение поля. Приложите сравнение версий и вид формы под рабочей ролью. Попросите пользователя проверить, находит ли он поле.
  • Расчет, проведение, права. Проверьте измененные модули и расчет на границе. Для движений сравните записи регистров до и после повторного проведения. Для прав проверьте разрешенное и запрещенное действие.
  • Обновление поставщика, расширение, перенос данных. Запишите версии платформы, конфигурации и расширений. При наличии расширений проверьте их применимость. Затем воспроизведите бизнес-сценарии на целевой комбинации. При изменении данных приложите контрольные итоги и порядок восстановления.

BSL Language Server ищет проблемы в исходниках. YAxUnit подходит для проверки расчетов, Vanessa Automation автоматизирует функциональные сценарии 1С. Для тестов с записью используйте изолированную базу и известные начальные данные. Некоторые клиентские тесты и операции с собственными транзакциями требуют отдельной очистки.
